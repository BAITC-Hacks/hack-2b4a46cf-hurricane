# Предметная область

Рабочий документ команды. Заполнен по [docs/hackathon/TASK.md](hackathon/TASK.md), устройство подбора шаг за шагом в [PIPELINE.md](PIPELINE.md). Разделы «Сущности» и «API» заморожены: изменения только через Alembic‑миграцию плюс `yarn api:types`, и о них говорят вслух всей команде.

## 1. Проблема

> Заказчик мероприятия вводит город, дату, тип события, категорию подрядчика и бюджет и получает до трёх карточек свободных подрядчиков с конкретным объяснением, почему каждый подходит, чтобы выбрать из каталога за минуту, а не перечитывать 15 профилей.

Аналоги:

- Маркетплейсы услуг (Profi, YouDo): паттерн «фильтры → список карточек». Берём карточку с ценой и городом. Отличаемся тем, что показываем не список, а три карточки с объяснением и явно говорим, почему остальные не прошли.
- Подборки «почему мы вам это рекомендуем» у Booking: одна строка причины под карточкой. Берём формат «факт про заказ → факт про подрядчика».

## 2. Основной сценарий

1. Пользователь открывает главную и заполняет форму: город, дата, тип мероприятия, категория, бюджет. Опционально длительность и язык. Списки значений приходят с бэкенда из каталога, не хардкодятся.
2. Система жёстко фильтрует каталог: город совпадает, категория входит в `categories`, дата не в `busy_dates`, тип входит в `event_formats`, `price_from_kzt` не выше бюджета, при указании длительности `max_hours` пустой или не меньше её, при указании языка он есть в `languages`. Каждый отсев считается по причине.
3. Система считает баллы прошедшим детерминированно: формат упомянут в описании, языки сверх запрошенных, запас по часам, настоящий профиль выше синтетического, цена не оценочная, цена до 80% бюджета. Плюс ранги близости описания к заказу по эмбеддингам OpenAI: три ближайших получают 3, 2 и 1 балл. Тай‑брейк по цене, потом по `id`.
4. Система раздаёт три роли: лучшее совпадение по баллам, самая низкая цена, самый дорогой в пределах бюджета. Если один подрядчик выиграл две роли, свободное место уходит следующему по баллам как «альтернатива». Одним вызовом LLM получает для каждого 1–2 предложения объяснения. В промпт уходят только вычисленные факты (доля бюджета и остаток, свободен на дату, формат, языки, часы, отличия от соседей по выдаче), LLM их формулирует по правилу «факт → что это даёт заказчику», а не придумывает. Общие фразы запрещены промптом и отсекаются проверкой, порядок карточек LLM не меняет.
5. Пользователь видит один из трёх исходов: карточки с объяснениями; «в городе нет такой категории»; «кандидаты есть (N), но никто не прошёл: занято на дату 4, дороже бюджета 2, не берут формат 1». Если карточек меньше трёх, под ними та же расшифровка причин и подсказки: соседняя дата, бюджет или город, по которым подбор перезапускается в один клик.

Некорректный ввод, который сценарий обязан переживать: дата вне окна 23.09.2026 – 31.12.2026 → 422 с текстом про окно каталога; бюджет ≤ 0 или нечисло → 422; значение не из словаря (город, категория, формат, язык) → 422; валидная пара «город + категория», которой нет в каталоге → исход «нет такой категории», не ошибка; OpenAI недоступен → карточки всё равно отдаются с объяснением из шаблона по тем же фактам и флагом `explanation_source: "template"`; пробелы и регистр во входе не важны.

## 3. Сущности

| Сущность | Поля (тип) | Связи | Из какого шага |
|---|---|---|---|
| `vendors` | `id str` (`HK-…`), `name str`, `categories list[str]`, `city str`, `price_from_kzt int`, `event_formats list[str]`, `languages list[str]`, `max_hours int \| null`, `busy_dates list[date]`, `description text`, `description_embedding list[float] \| null` (256 измерений, считается при сиде), `synthetic bool`, `city_imputed bool`, `price_imputed bool`, `created_at` | | шаги 2–4, загрузка `python -m src.seed` из `app/data/vendors.csv`, upsert по `id` |

Списки хранятся как `ARRAY(String)` / `ARRAY(Date)`, каталог маленький, join‑таблицы и индексы кроме PK не нужны. Seed идемпотентный: запускается после миграций в compose (сервис `seed`) и в `preDeployCommand` на Railway.

Одна таблица `vendors`, независимый каталог, читается фильтром. История запросов не хранится: подбор детерминирован, его повторяет та же ссылка.

## 4. API

| Шаг | Метод и путь | Вход (схема) | Выход (схема) | Ошибки |
|---|---|---|---|---|
| 1 | `GET /catalog/options` | | `CatalogOptionsOut` (`cities`, `categories`, `event_formats`, `languages`: `list[OptionOut]`; `date_from`, `date_to`) | 500 |
| 1 | `GET /vendors` | | `list[VendorOut]`, весь каталог, сортировка по `id`, без пагинации | 500 |
| 2–5 | `POST /recommend` | `RecommendIn` (`city`, `event_date`, `event_format`, `category`, `budget_kzt`, `duration_hours?`, `languages: list`, пустой = любой) | `RecommendOut` (`outcome: Literal["matched","no_category_in_city","no_candidates_pass"]`, `cards: list[VendorCardOut]`, `pool_size`, `rejections: list[RejectionOut]` по причинам `busy`/`format`/`budget`/`duration`/`language` со счётчиками, `suggestions: list[SuggestionOut]` вида `date`/`budget`/`city`) | 422, 502 |

Словари фильтров. Наружу и в БД ходят только латинские `value`, кириллица живёт в `label`: в опциях, карточках и текстах для LLM. Сид переводит подписи из CSV в `value`. Маппинг `value ↔ label` один, `Option(StrEnum)` в `app/src/schemas.py`, поля `RecommendIn` объявлены этими `StrEnum`, поэтому в `openapi.json` и в `api-types.ts` они приходят как enum. `OptionOut` = `{value, label}`, порядок списков фиксированный, как в таблице.

| Поле | `value` → `label` |
|---|---|
| `city` | `almaty` Алматы, `astana` Астана, `abroad` Зарубежье |
| `event_format` | `wedding` свадьба, `toi` той, `corporate` корпоратив, `conference` конференция, `anniversary` юбилей, `birthday` день рождения |
| `language` | `ru` русский, `kk` казахский, `en` английский |
| `category` | `host` Ведущий, `ceremony-host` Ведущий церемонии, `photographer` Фотограф, `videographer` Видеограф, `photo-booth` Фото и видеобудки, `florist` Флорист, `decorator` Декоратор, `gifts` Подарки и сувениры, `live-band` Лайв-бэнд, `instrumentalist` Инструменталист, `national-ensemble` Национальный ансамбль, `dance-group` Танцевальный коллектив, `show` Шоу-программа, `banquet-hall` Банкетный зал, `restaurant` Ресторан, `hotel` Отель, `country-venue` Загородная площадка |

Новое значение в CSV без записи в словаре роняет сид с ошибкой, а не тихо пропадает из фильтра.

`VendorOut`: `id`, `name`, `categories: list[OptionOut]`, `city: OptionOut`, `price_from_kzt`, `event_formats: list[OptionOut]`, `languages: list[OptionOut]`, `max_hours`, `description`, `synthetic`, `price_imputed`, `city_imputed`. Без `busy_dates`: занятость видна только через подбор на конкретную дату.

`VendorCardOut`: `id`, `name`, `categories: list[OptionOut]`, `city: OptionOut`, `price_from_kzt`, `languages: list[OptionOut]`, `max_hours`, `role: Literal["best_match","best_price","premium","alternative"]`, `explanation`, `explanation_source: Literal["llm","template"]`, `matched_on: list[str]` (какие условия совпали, для бэджей на карточке), `synthetic`, `price_imputed`, `city_imputed`.

`SuggestionOut`: `kind`, `count` (сколько подрядчиков пройдёт при ослабленном условии) и одно из `event_date`, `budget_kzt`, `city`.

Детерминизм: ранжирование и роли без LLM, `seed` в вызове объяснений. Один вызов LLM на все три карточки с таймаутом 8 с, без ретраев: при таймауте сразу шаблонные объяснения, чтобы ответ пришёл в ориентир 10 с.

## 5. Экраны

Паттерн: **форма → результат**.

Экран 1 (`ui/src/routes/index.tsx`): компактный фильтр и под ним список подрядчиков из `GET /vendors`. Экран 2 (`ui/src/routes/results.tsx`): результат подбора из `POST /recommend`.

- Фильтр: 5 обязательных полей и раскрывающийся блок «Длительность, язык». Одна главная кнопка «Подобрать». Значения списков из `GET /catalog/options`.
- Результат: загрузка с текстом «Подбираю…», три исхода из шага 5, ошибка с подсказкой что делать. У синтетического профиля бэдж «синтетический профиль».
- Ссылка на подбор: параметры фильтра живут в query string (`validateSearch` в TanStack Router), имена как в `RecommendIn`: `/results?city=almaty&event_date=2026-11-14&event_format=wedding&category=photographer&budget_kzt=300000`, в ссылке только латиница и цифры. Открыли ссылку с полным набором обязательных параметров, `POST /recommend` уходит сразу. Бэкенду для этого ничего не нужно: подбор детерминирован, по той же ссылке тот же порядок карточек.
