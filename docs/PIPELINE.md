# Пайплайн подбора: как устроен и почему

Один запрос `POST /recommend` проходит семь шагов. Код: `app/src/recommend.py` (шаги 2, 4, 5), `app/src/filters.py` (шаг 3), `app/src/embeddings.py` (шаг 4), `app/src/suggestions.py` (шаг 6), `app/src/facts.py` и `app/src/explain.py` (шаг 7). LLM участвует только на последнем шаге и только как редактор текста.

```
заказ ─▶ 1 валидация ─▶ 2 пул из БД ─▶ 3 жёсткие фильтры ─▶ 4 скоринг ─▶ 5 три роли ─▶ 6 подсказки ─▶ 7 объяснения ─▶ ответ
                            │                  │                                                         │
                            └ пусто:           └ никто не прошёл:                                        └ LLM (8 с) или шаблон
                              no_category_in_city  no_candidates_pass
```

## Шаги

1. **Валидация входа.** Pydantic один раз на границе: город, дата в окне календаря 23.09–31.12.2026, формат, категория, бюджет. Длительность и языки опциональны. Дальше по коду ходят простые типы.
2. **Пул из базы.** Один SQL-запрос: все подрядчики этого города с этой категорией. Площадки лежат в том же каталоге, поэтому «зал на 14 ноября» это тот же запрос с другой категорией. Пул пустой → исход `no_category_in_city`, в ответе подсказки, в каких городах категория есть.
3. **Жёсткие фильтры в фиксированном порядке:** занят на дату → не берёт формат → цена выше бюджета → часов меньше, чем нужно → нет нужного языка. Отсеянный считается по первой сработавшей причине, поэтому счётчики отказов складываются ровно в размер пула и честно отвечают «почему меньше трёх». Никто не прошёл → исход `no_candidates_pass`.
4. **Скоринг прошедших.** Параллельно с запросом в базу считается эмбеддинг заказа («Ведущий для мероприятия «свадьба», языки: русский, казахский, 6 часов на площадке»). Косинусная близость к векторам описаний, округлённая до тысячных, даёт ранги: три ближайших описания получают +3, +2, +1. Без ключа OpenAI или при сбое ранги пустые, скоринг работает без них. Остальные баллы: формат упомянут в описании (+3), каждый язык сверх запрошенных (+1), запас часов от 2 ч (+1), настоящий профиль, не синтетический (+2), цена не оценочная (+1), цена до 80% бюджета (+1). Ничьи разрешаются ценой, потом `id`. Отсюда детерминизм: тот же запрос → тот же порядок.
5. **Три роли вместо топ-3.** `best_match` (максимум баллов), `best_price` (самая низкая цена), `premium` (самая высокая цена в пределах бюджета). Если один подрядчик выиграл две роли, свободное место уходит следующему по баллам как `alternative`, и его объяснение называет разрыв с `best_match`: дешевле или дороже на сколько, цена оценочная, профиль синтетический или формат не упомянут в описании. Роли дают разброс по смыслу, а не три похожих подрядчика.
6. **Подсказки, если прошло меньше трёх.** Соседние даты в пределах ±3 дней, где свободных больше, бюджет и длительность, при которых добавились бы ещё кандидаты. Если не прошёл никто, ещё и города, где подрядчики этой категории проходят все условия заказа. Фронт может перезапустить запрос по подсказке в один клик.
7. **Объяснения.** Факты считает код: доля цены от бюджета и остаток, свободен на дату, формат, языки, часы, чем отличается от двух соседей по выдаче, сколько в категории заняты на дату (только у первой карточки). LLM получает эти факты и описание подрядчика и пишет 1–2 предложения по правилу «факт → что это даёт заказчику». Промпт: `app/src/explain_prompt.md`. Один вызов на все три карточки, `seed`, таймаут 8 с, без ретраев. Ответ проверяется: длина 20–320 символов, не больше двух предложений, каждое число в тексте встречается в фактах карточки или в описании подрядчика (свои проценты и остатки модель посчитать не может), языки только из профиля подрядчика, нет общих фраз и служебных слов («карточка», «подборка»), нет латиницы внутри русских слов, нет «цена оценочная» там, где цена в каталоге точная. Шаблонный текст тоже ровно два предложения. Не прошёл или LLM недоступна → текст собирает шаблон из тех же фактов. Поле `explanation_source` в карточке показывает, откуда текст: `llm` или `template`.

## Почему так

- По задаче ценность в объяснении, а не в сортировке. Поэтому факты считает код, а модель их только озвучивает. Числа и языки в её тексте сверяются с фактами и профилем, сравнительные формулировки («единственный с английским», «уступает первому только тем, что») тоже приходят из кода, а не от модели.
- Детерминизм и фильтр занятости это жёсткие требования. LLM их не гарантирует, код гарантирует.
- Роли решают требование «карточки нельзя перепутать»: у каждой своя причина попасть в тройку и свои факты-отличия.
- Шаблонный запасной путь нужен, потому что демо проверяют вживую, а внешний API может упасть. Ответ приходит всегда и укладывается в 10 секунд.
- Три исхода это три разных значения `outcome` в ответе, фронт показывает их разными экранами, а не пустым списком.

## Что рассматривали вместо этого

| Вариант | Почему не взяли |
|---|---|
| Чистый LLM-ранкер: отдать модели весь пул и заказ, попросить выбрать трёх и объяснить | Недетерминировано, медленно, модель может пропустить занятого или придумать факт |
| Эмбеддинги как фильтр или как единственный рейтинг | Порог близости нечего обосновать на 76 записях, а фильтр по смыслу скрыл бы честные отказы. Поэтому эмбеддинги только ранжируют прошедших жёсткие фильтры, и ближайшее описание отмечается в фактах карточки |
| pgvector | Один SQL-запрос отдаёт весь пул города и категории, до 10 строк: косинус на Python быстрее, чем расширение и индекс |
| Только шаблоны без LLM | Детерминировано и бесплатно, но тексты сухие. Оставлено запасным путём |
| Один рейтинг с весами и топ-3 | Часто даёт трёх одинаковых подрядчиков. Роли дают разброс: лучший, дешёвый, премиум |
| Агент с инструментами, который сам вызывает фильтры и базу | Лишняя сложность и лишние секунды для каталога такого размера |

## Как проверить по Definition of Done

Автоматически: `uv run pytest` в `app/` прогоняет сценарии ниже по CSV без базы и без LLM (объяснения шаблонные). Вживую:

Бэкенд поднят (`python dev.py` или `docker compose up`), ключ OpenAI в `.env`. Запросы к `http://localhost:8000/recommend`, тело JSON.

| Проверка | Запрос | Что смотреть в ответе |
|---|---|---|
| Плотная категория, осень | `almaty`, `2026-10-17`, `wedding`, `host`, бюджет `1500000`, `duration_hours: 6`, `languages: ["ru","kk"]` | `outcome: matched`, 3 карточки с разными `role`, тексты не перепутать |
| Редкая категория | `almaty`, `2026-10-20`, `wedding`, `florist`, бюджет `400000` | 1 карточка, `pool_size: 3`, `rejections: busy 2`, подсказки соседних дат |
| Кандидаты не проходят | `astana`, `2026-10-10`, `corporate`, `photographer`, бюджет `600000` | `outcome: no_candidates_pass`, `rejections: format 3` |
| Категории нет в городе | `abroad`, любая дата, `host` | `outcome: no_category_in_city`, `suggestions` с городами |
| Две даты | запрос из первой строки на `2026-10-17` и `2026-12-19` | 3 карточки против 1, в тексте первой карточки «9 из 10 заняты», подсказки соседних дат |
| Детерминизм | любой запрос дважды | одинаковый порядок `id`. Формулировки LLM могут отличаться, порядок нет |
