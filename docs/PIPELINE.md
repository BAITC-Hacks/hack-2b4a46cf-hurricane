# Подбор и проверка рекомендаций

`POST /recommend` выполняет цепочку: пул города и категории → жёсткие фильтры → ранжирование и выбор до трёх карточек → проверенные факты → объяснения → UI.

Код в `app/src/recommend.py` проверяет дату, формат, цену «от», длительность и все запрошенные языки. Отказы считаются по первой причине в фиксированном порядке. `pool_size` — весь пул города и категории, `passed_count` — все прошедшие фильтры, `cards` — показанные (не больше трёх). Это разные числа. Пустой пул даёт `no_category_in_city`, непустой пул без прошедших — `no_candidates_pass`.

Скоринг и роли выбирают карточки детерминированно: при равенстве учитываются цена и ID. Модель не выбирает подрядчиков и не меняет порядок. `app/src/facts.py` строит допустимые отличия из структурированных полей и конкретных фрагментов описания, сравнивая показанные профили. Если подтверждённого отличия нет, код прямо сообщает об этом. Дата, цена «от», оценочный флаг, формат, запрошенные языки и предел длительности добавляются кодом в `app/src/explain.py`.

LLM получает только список допустимых фактов с ID и при доступности выбирает один ID для каждого профиля. Код проверяет принадлежность ID профилю и собирает итоговые два предложения из собственных формулировок. При недоступности LLM, неверном JSON, пустом ответе или неизвестном/чужом ID выбирается первый проверенный факт. `explanation_source` показывает `llm` для принятого выбора и `template` для резерва. Свободный текст модели пользователю не передаётся. Оценочная цена показывается в UI по `price_imputed` независимо от модели; синтетические профили помечены по `synthetic`.

`ui/src/components/SearchHints.tsx` отдельно объясняет короткую и пустую выдачу по `pool_size`, `passed_count` и `rejections`. Для каждого отказа показана фактическая причина. Подсказки соседней даты и бюджета рассчитываются кодом.

## Ограничения

- Детали описаний в каталоге не проходят внешнюю проверку: формулировка «в описании указано» обозначает источник утверждения.
- Не у каждого профиля есть различающая деталь. Например, у Поньо и Рамь совпадают цена, язык и длительность, а общая часть описания не создаёт честного различия. В таком случае карточка сообщает о равном соответствии.
- Список конкретных деталей в `facts.py` консервативен: неподдержанные фразы не превращаются в обещания. Другие описания могут получить только структурированное отличие или честную оговорку.
- Таймаут LLM составляет 8 секунд, базы — 5 секунд; суммарное время ответа не гарантировано меньше 10 секунд.
- Минимальная цена не является фиксированной итоговой стоимостью или гарантией остатка бюджета.

## Проверочные сценарии

Проверки основного API находятся в `app/tests/test_recommend.py`; локально: `cd app`, `uv run pytest`, `uv run ruff check .`, `uv run ruff format --check .`. Интерфейс проверяется вручную через `/results` и параметры в URL.

| Сценарий | Запрос | Ожидаемое по текущему CSV |
|---|---|---|
| Флористы | Алматы, свадьба, 13.11.2026, 300 000 ₸ | 2 прошли из 3, 0 заняты, 1 дороже бюджета; у Чоппера цена оценочная |
| Короткий пул без отказов | Алматы, свадьба, подарки, 23.09.2026, 50 000 000 ₸ | 2 из 2 проходят, `rejections` пуст; UI объясняет, что в категории всего два профиля |
| Ансамбли | Алматы, свадьба, 09.10.2026, 500 000 ₸ | Факты из описания или честное равное соответствие, без обещаний о двух часах |
| Ведущие | Алматы, свадьба, 11.10.2026, 1 500 000 ₸ | У Эмилии оценочная цена |
| Смена даты | Флористы, тот же бюджет; 14, 15 и 21.11.2026 | Тихиро; Чоппер; пусто, 3 заняты по первой причине отсева |
| Допусловия | Ведущие, 17.10.2026, 1 500 000 ₸, 6 ч, русский и казахский | Все показанные проходят оба языка и длительность |
| Повтор и резерв | Те же запросы, модель недоступна или вернула чужой ID | Те же ID и порядок; два предложения из проверенных фактов |
