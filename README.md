# EventMatch: подбор event-подрядчиков

Заказчик мероприятия вводит город, дату, формат, категорию и бюджет и получает до трёх свободных подрядчиков из каталога. Объяснения собираются из проверенных полей и конкретных сведений описания. Если подтверждённого отличия между карточками нет, сервис говорит об этом прямо. Короткая и пустая выдача сопровождаются числами и причинами отбора.

Демо: https://ui-production-d923.up.railway.app · API: https://app-production-b973.up.railway.app/health

Задача хакатона: [docs/hackathon/TASK.md](docs/hackathon/TASK.md). Пайплайн и актуальные проверочные сценарии: [docs/PIPELINE.md](docs/PIPELINE.md). Предметная область и схемы API: [docs/DOMAIN.md](docs/DOMAIN.md).

## Требования → статус

| Требование | Статус | Где в коде |
|---|---|---|
| Вход: город, дата, тип мероприятия, категория, бюджет; опционально длительность и язык | ✅ | `RecommendIn` в `app/src/schemas.py` |
| Выход: до 3 карточек с именем, категорией, городом, ценой «от» и объяснением в 1–2 предложения | Реализовано; различия ограничены данными | `app/src/explain.py`, `app/src/facts.py` |
| Занятый на дату не попадает в выдачу, площадки идут тем же фильтром | ✅ | `get_rejection_reasons` в `app/src/recommend.py` |
| Подходящих меньше трёх: показать сколько есть и почему меньше | ✅ | `pool_size`, `passed_count`, `rejections`, экран `ui/src/components/SearchHints.tsx` |
| Детерминизм: тот же запрос, тот же порядок карточек | ✅ | `pick_role_vendors`: баллы, цена, `id`; LLM порядок не меняет |
| Три исхода различимы явно | ✅ | `outcome` в `RecommendOut`, три экрана в `results.tsx` |
| Ответ до 10 секунд | Цель, не гарантия | отдельные таймауты БД 5 с и LLM 8 с |
| Объяснения не взаимозаменяемы | По подтверждённым различиям; иначе честная оговорка | `app/src/facts.py` |
| Видно, где настоящий профиль, а где синтетический | ✅ | флаг `synthetic` в карточке, бэдж в `ui/src/components/VendorCard.tsx` |

## Как работает подбор

1. **Пул.** Из базы берутся подрядчики нужного города и категории. Пусто → исход «в этом городе такой категории нет» и список городов, где она есть.
2. **Фильтры.** Занят на дату, не берёт формат, дороже бюджета, мало часов, нет языка. Каждый отсеянный считается по первой причине, счётчики уходят в ответ. Никто не прошёл → исход «кандидаты есть, но не проходят».
3. **Баллы и роли.** Прошедшие получают баллы за упоминание формата в описании, лишние языки, запас часов, настоящий профиль, точную цену и цену до 80% бюджета. Три карточки это три роли: лучшее совпадение, самая низкая цена, самый дорогой в бюджете. Ничьи решает цена, потом `id`, поэтому порядок стабилен.
4. **Объяснения.** Код формирует дату, цену «от», оценочный флаг, соответствие условиям и подтверждённые отличия. OpenAI может выбрать ID одного допустимого факта для каждого профиля. Код проверяет ID и собирает два предложения. При сбое или неверном ответе выбирается проверенный резервный факт. Численность пула и причины исключения выводятся отдельно от карточек.
5. **Подсказки.** Если прошло меньше трёх, в ответе соседние даты в пределах трёх дней и бюджет, при которых кандидатов больше. Фронт перезапускает подбор по подсказке в один клик.

LLM участвует только в шаге 4 как селектор проверенного факта. Состав и порядок карточек от неё не зависят. Подробности: [docs/PIPELINE.md](docs/PIPELINE.md).

## Архитектура

```
ui (React + Vite, Railway) ──HTTP/JSON──▶  app (FastAPI, Railway)  ──▶  Postgres (Railway)
                                              │
                                              └──▶ OpenAI API
```

Бэкенд `app/src/`:

- `main.py` роутеры, CORS, `/health`. `catalog.py` словари фильтров `GET /catalog/options` и каталог `GET /vendors`.
- `recommend.py` `POST /recommend`: пул, фильтры, баллы, роли, подсказки. `facts.py` проверенные отличия; `explain.py` выбор факта и сборка текста; `llm.py` клиент OpenAI с таймаутом.
- `schemas.py` схемы входа и выхода и словари `value ↔ label`. `models.py` таблица `vendors`, миграции в `app/migrations/`. `seed.py` загрузка `app/data/vendors.csv`.

Фронтенд `ui/src/`:

- `routes/index.tsx` форма фильтров и каталог. `routes/results.tsx` результат подбора: загрузка, три исхода, причины отказа, подсказки. `components/VendorCard.tsx` карточка с ролью и бэджем синтетического профиля.
- `api.ts` все запросы через `openapi-fetch`, типы в `api-types.ts` сгенерированы из `/openapi.json`.

## Технологии и данные

- Бэкенд: Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2, asyncpg, `openai`, uv; pytest для проверок API.
- Фронтенд: React 19, TypeScript, Vite 7, TanStack Router и Query, Tailwind CSS v4, shadcn на Base UI, Lingui (ru / kk / en), yarn.
- База: PostgreSQL 17. Инфраструктура: Railway, конфигурация в `.railway/railway.ts`.
- Модель: `OPENAI_MODEL`, по умолчанию `gpt-5.4-mini`, вызов с `seed` и `response_format: json_object`.
- Данные: каталог организатора, 66 профилей, `app/data/vendors.csv`. Загружается командой `python -m src.seed`, upsert по `id`, повторный запуск безопасен. В compose это делает сервис `seed` после миграций, на Railway `preDeployCommand`. К 13 синтетическим профилям датасета добавлены 10 своих (`HK-90014` – `HK-90023`, `synthetic: True`) в категории, где было по одному-два подрядчика: флористы, ведущие церемоний, фото- и видеобудки, подарки, зал и отель в Астане, видеограф, инструменталист. Занятые даты у них сгенерированы по сезонности задачи: 40% дней осенью, 75% в декабре и 90% на декабрьских выходных. На карточке синтетический профиль помечен бэджем.

## Запуск

Нужны Docker Desktop или Podman Desktop с Compose и Python 3.9+.

```bash
python dev.py
```

Скрипт проверит инструменты, создаст `.env` из `.env.example`, включит git-хуки, подберёт свободные порты, соберёт контейнеры и дождётся `/health`. Compose поднимает Postgres, применяет миграции, загружает каталог, затем стартует API и фронтенд. Адреса: UI http://localhost:5173, API http://localhost:8000/docs.

После первого запуска вписать в `.env` `OPENAI_API_KEY` и повторить `python dev.py`. Без ключа всё работает, объяснения будут шаблонными.

Другие команды: `python dev.py down` остановить (`down -v` также удалит базу), `python dev.py logs app` логи, `python dev.py status` состояние контейнеров. Без скрипта то же самое делает `docker compose up --build`.

### Разработка без Docker

```bash
# бэкенд, нужен запущенный Postgres, например `docker compose up db`
cd app && uv sync && uv run alembic upgrade head && uv run python -m src.seed && uv run python -m src

# фронтенд
cd ui && yarn install && yarn dev
```

После изменения схем на бэкенде перегенерировать типы фронтенда: `yarn api:types` в `ui/` при запущенном API, файл `ui/src/api-types.ts` коммитится. Проверки перед коммитом: `uv run pytest`, `uv run ruff check . && uv run ruff format --check .` в `app/`, `yarn lint` и `yarn build` в `ui/`. Хук на сообщения коммитов: `git config core.hooksPath .githooks`.

## Как проверить основной сценарий

Через интерфейс:

1. Открыть http://localhost:5173, выбрать город, дату, формат, категорию и бюджет. Язык и длительность в блоке «Дополнительные условия». Под формой загружается каталог, «Показать всех подрядчиков» раскрывает весь список.
2. Нажать «Подобрать»: откроется `/results` с фильтрами в URL. Появятся карточки с ролями и объяснениями или один из двух пустых исходов с причинами и подсказками.
3. Скопировать URL результатов и открыть в новой вкладке: тот же подбор загрузится без формы, порядок карточек тот же.

Через API, три запроса из Definition of Done:

```bash
# плотная категория на осеннюю дату
curl -X POST http://localhost:8000/recommend -H 'content-type: application/json' \
  -d '{"city":"almaty","event_date":"2026-10-17","event_format":"wedding","category":"host","budget_kzt":1500000,"duration_hours":6,"languages":["ru","kk"]}'

# редкая категория: проверьте pool_size, passed_count и rejections
curl -X POST http://localhost:8000/recommend -H 'content-type: application/json' \
  -d '{"city":"almaty","event_date":"2026-10-20","event_format":"wedding","category":"florist","budget_kzt":400000}'

# кандидаты есть, но никто не проходит условия
curl -X POST http://localhost:8000/recommend -H 'content-type: application/json' \
  -d '{"city":"astana","event_date":"2026-10-10","event_format":"corporate","category":"photographer","budget_kzt":600000}'
```

Пул, число прошедших, причины исключения и пометки цены проверяются отдельно от текста карточек. Актуальная таблица сценариев: [docs/PIPELINE.md](docs/PIPELINE.md).

## Известные ограничения

- Порядок и состав карточек детерминированы. Если у профилей нет подтверждённых различий, объяснение может честно сообщать об одинаковом соответствии.
- Каталог не подтверждает факты описаний внешними источниками; такие детали явно приписываются описанию. Цена «от» не равна итоговой стоимости.
- Поиск «по смыслу описания» сделан регуляркой по формату мероприятия в тексте профиля, без эмбеддингов.
- Каталог на главной показывает первые шесть карточек до нажатия «Показать всех подрядчиков».
- Для части новых строк интерфейса нет переводов на казахский и английский.
